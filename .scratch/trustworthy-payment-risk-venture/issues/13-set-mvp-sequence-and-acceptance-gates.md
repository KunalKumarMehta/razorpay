# Set the MVP Scope, Build Sequence, and Acceptance Gates

Type: grilling
Status: resolved
Blocked by: 01, 08, 10, 11, 12

## Question

What is the smallest coherent submission, what is explicitly deferred, in what dependency order should an agent-driven solo build proceed before the verified deadline, and what evidence-based gate determines whether each slice is kept, simplified, replaced, or cut?

## Answer

**Release bar and coherent slice.** Build a contract-conformant, honestly measured vertical slice rather than a demo-only reduction. It must implement the full authoritative lifecycle: Admission Rejection; evidence admission; multilingual voice/text investigation; Payment Intent extraction and confirmation; deterministic `BLOCKED`, `HOLD`, `STEP_UP_REQUIRED`, and `ELIGIBLE_FOR_HANDOFF`; step-up evidence; material-edit invalidation; Handoff Grant issue and atomic consumption; fake pending-item handoff; ambiguity/Reconciliation Required; replay rejection; and fail-closed model/schema failure. The focused UI gives prominence to three paths—eligible handoff, step-up/Hold, and mutation or ambiguous replay—while automated tests and the evaluator cover every transition. A missed metric is published as a failed gate with the unsafe route disabled; it does not justify hiding evidence or missing the submission.

**Required implementation.** Preserve typed commands and pure transitions, a deterministic frozen Policy Gate, canonical intent/snapshot hashes, SQLite persistence, single-use expiring HMAC grants, atomic replay protection, the deterministic fake adapter, ambiguity/reconciliation semantics, and a verifiable per-case audit hash chain. Run real frozen local multilingual ASR, deterministic candidates/spans plus constrained multilingual extraction, mandatory operator confirmation, and quality-gated AASIST as a non-authoritative diagnostic. Select the smallest passing ASR and extraction profiles through one bounded primary-versus-nominated-challenger shootout on the same smoke evidence and hardware; allow no broad model search or sealed-set tuning. Weak AASIST remains published but is demoted to unavailable/unproven in product behavior unless its stress-set ROC-AUC confidence interval excludes 0.5. OCR is cut.

**Executable evidence spine.** Treat schemas, a versioned deterministic simulator, structurally independent declarative oracle, scorer, manifests, and a cross-language smoke set as executable specifications. Grow them mechanically into the agreed 45-case development corpus, 90-case sealed corpus, 27 Critical Safety Cases repeated three times, stability subset, and component stress sets. Use fictitious, disclosed text and synthetic/TTS media with separated templates, voices, seeds, sources, and degradation recipes. Freeze only after invariant checks and the required manual audits. The no-PayoutProof comparison is an independent, versioned paired-task model using predeclared observable operator interactions and identical evidence/context/policy. Count actual operator gestures only; publish paired distributions, exceptions, and largest-case-removed sensitivity. The 30% interaction-reduction gate applies only without correctness degradation. Founder timing and all money effects remain descriptive or modelled, never customer productivity, ROI, or prevented-loss evidence.

**Slice gates.** Apply one criticality-aware rule at predeclared checkpoints. Keep a slice when its semantic tests, reproducibility, typed integration contract, and declared latency/resource budget pass. Simplify optional breadth, polish, concurrency, or operations when core safety semantics pass. Replace only through a bounded, interface-compatible nominated challenger that materially improves a failed required metric inside its timebox. Cut an optional slice when neither simplification nor replacement can pass in time. Simulator/oracle/scorer, exact-intent state, deterministic policy, grants/replay, audit, required inference, and reproducibility are never silently cut; a remaining failure disables the unsafe route and narrows the claim.

The verification spine has zero-tolerance gates: every generated artifact validates and reconciles; repeated seeds/configurations reproduce structured artifacts and hashes; simulator truth and oracle remain separate; fixed oracle fixtures pass; runtime policy agrees with the oracle on all development cases; transitions and reason codes are total and deterministic; property tests yield zero eligible outcomes for incomplete, ambiguous, unsupported, contradicted, mutated, unauthorized, replayed, or failed cases; concurrent/repeated grant use cannot create duplicate pending items; ambiguity cannot retry; restart preserves authority; and intentional audit mutation/deletion is detected. A red authority gate stops downstream work except operational simplification.

ASR must reach at least 95% material-entity accuracy overall, no language below 90%, at least 95% correct unusable-input abstention, no silent empty success, and enough headroom for complete warm/cold voice p95 limits of 60/120 seconds. Extraction must produce 100% schema-valid outputs, at least 95% exact material-field binding and correct abstention, zero unsupported fields accepted as confirmed, and enough headroom for the five-second warm-text p95. AASIST must always return typed provenance or explicit quality abstention, remain stable on repeats, and never relax policy. The integrated local release must pass from a clean checkout: headless flow first, then all three guided UI paths; no client-authored state or outcomes; one exact fake pending item; visible safe mutation/ambiguity/replay behavior; persistent verifiable state/audit; redacted logs/exports; deterministic demo reset; and a walkthrough short enough to leave room in the five-minute pitch. Native local execution is canonical; Docker Compose is included only if already green without delay.

**Dependency order and agent protocol.** Proceed in this order: repository/package skeleton and machine-readable handoff ledger; schemas; simulator/oracle/scorer/manifests/smoke evidence; lifecycle/policy; hashes/persistence/grants/replay/audit/fake adapter; headless zero-tolerance gate; bounded model shootouts and freeze; inference integration and development-corpus growth; API/generated types/minimal focused UI; fresh-setup integrated gate; full rehearsal and audits; configuration/manifest seal; sealed run and scoring; clean-clone/package verification; pitch; form reconciliation; submission. One integration agent owns authoritative schemas, dependency graph, lockfiles, release branch, and acceptance. After interfaces freeze, bounded parallel lanes may generate media/fixtures, benchmark nominated models, implement the web shell, or prepare documentation. One agent writes a module at a time; every lane returns a small reviewable change with commands, results, assumptions, artifact manifest, and no unrelated edits, and the integrator reruns the receiving gate. No lane may alter truth, oracle rules, policy, sealed manifests, or thresholds to force a pass. The ledger records interface version, owner, gate status, commands, hashes, and known failures.

**Explicit deferrals.** Keep closed until after the frozen submission: RazorpayX and all live/external payment or approval adapters; OCR/documents; public hosting/static fixture; equal polish for all prototype paths, responsive edge cases, animation, and cosmetics; enterprise IAM; production evidence-vault encryption/key management, PII isolation, and retention automation; durable multi-process recovery, SSE, OpenTelemetry infrastructure, Postgres/object storage, webhook ingestion, HA, and deployment hardening; broad routing, runtime multi-agent behavior, iterative model search, training/fine-tuning, and detector fusion; Docker Compose unless already green; customer validation; realized ROI/loss claims; live money; and a three-reviewer timing claim. Generated plausibility does not reopen a deferral. Label each item post-MVP hardening or not evaluated.

**Sealing and final release.** One immutable result belongs to each Evaluation Version. Do not inspect sealed expected answers to improve the system. Score every attempt; retain and label infrastructure reruns; use only predeclared prehashed spares for pre-result packaging corruption. Any material code, model, prompt, threshold, policy, normalization, simulator, oracle, or manifest change requires genuinely fresh separated evidence and a complete new run. If the recovery window cannot produce it, publish the original miss. Before the irreversible form submission, one release manifest must prove that the public repo is cloneable, secret-free, reproducible, source/license-aware, and complete; required commands and redistributed-or-referenced resources work; architecture, configuration, hashes, raw outputs, results, failures, and limitations agree; the accessible video is at most five minutes and matches the frozen claims; and repo, video, and form agree in a signed-out link check. Claim drift, inaccessible links, secrets, irreproducible headline evidence, video overrun, unsafe enabled behavior, false claims, or missing required links block release. Honestly disclosed metric misses do not.
