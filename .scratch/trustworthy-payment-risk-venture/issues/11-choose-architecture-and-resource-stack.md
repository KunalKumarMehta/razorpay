# Choose the Agent Architecture and Resource Stack

Type: grilling
Status: resolved
Blocked by: 03, 08, 09, 10

## Question

Which components, agent topology, deterministic services, data stores, model routing, interfaces, deployment shape, observability, and cost-aware resources best satisfy the selected behavior and evaluation contract without creating unnecessary build or vendor risk?

## Answer

**Architecture and authority.** Build PayoutProof as a production-shaped modular monolith: a Vite/React presentation layer, authoritative Python FastAPI/Pydantic control plane, and isolated Python inference worker behind typed ports. Organize the control plane around `admission`, `case_workflow`, `evidence`, `investigation`, `intent`, `policy`, `grant`, `handoff`, `audit`, and `evaluation`. One explicit typed case workflow invokes stateless bounded capabilities; there is no runtime multi-agent conversation or swarm. Deterministic code alone advances state, freezes snapshots, applies budgets, invokes the Policy Gate, and controls handoff. Model workers have no payout credentials, policy authority, or adapter route.

**Evidence flow.** Voice notes and text/messages are required; OCR/documents are a later noncritical adapter. Admission validates the Processing Authority Record, file allowlist, size/duration limits, magic bytes, bounded media normalization, and hashes before model access. Rejected authority or malformed/prohibited input opens no Risk Case; unusable admitted evidence fails closed inside the case. A deterministic preprocessor creates immutable hashed derivatives. Each capability receives only its minimum input and returns typed provenance-linked findings using the five agreed truth states; workers receive no shared memory, broad case history, policy, grants, or credentials. Run decode/quality checks, ASR, quality-gated AASIST, deterministic candidates, and schema-constrained extraction in a frozen resource-aware order, releasing models between stages unless benchmarked parallelism is demonstrably stable.

**State, API, and jobs.** Implement the lifecycle as a pure typed transition function over current state plus a validated command, atomically persisting new state, append-only events, and jobs. A SQLite job table supplies leases, explicit terminal states, deadlines, and bounded attempts; no broker or workflow framework is required. Voice work is durable and asynchronous, with polling or SSE progress, and survives client disconnects. The API exposes read projections and typed commands carrying expected case version, actor context, and idempotency key; clients cannot patch authoritative state or submit Policy Outcomes. Run one active case/model request on the reference machine, permit at most one retry for a classified pre-result transient infrastructure failure, and turn every other timeout, schema, evidence, decode, or model failure into a visible scored fail-closed state.

**Policy, binding, grants, and audit.** The Policy Gate is a total pure Python evaluator over an immutable, validated, hash-bound YAML/JSON policy containing required evidence, quality/freshness thresholds, destination and amount rules, separation of duties, canonical outcomes, stable reason codes, and exact next steps. It performs no fetching, free-text interpretation, code execution, model call, or repair. Canonically normalize and serialize material fields, then SHA-256 hash evidence manifests, Payment Intents, and Risk Case snapshots. Issue a short-lived HMAC-signed Handoff Grant bound to tenant, case, intent/snapshot hashes, policy version, actor constraints, nonce, and expiry. Atomically verify and consume its nonce and record the idempotent adapter attempt before any network call; post-send uncertainty becomes Reconciliation Required and never reopens or blindly retries the grant. Store redacted append-only audit events in a per-case SHA-256 hash chain, verify it on read/export, and sign sealed-run manifests. Describe this as tamper-evident, not tamper-proof.

**Storage, security, and identity.** Use SQLite WAL for cases, snapshots, policies, jobs, grants, adapter attempts, and audit events, plus a private content-addressed filesystem vault for raw media. Keep only hashes and redacted structured data in SQLite and provide deterministic JSON/JSONL exports; preserve repository ports for future Postgres/object storage. Encrypt vault objects with authenticated encryption under derived per-object keys and versioned metadata; inject the local master key, grant secret, and test credentials at runtime with startup validation, `.env.example`, and a gitignored secret file or OS keychain. Raw media, transcripts, destinations, webhook bodies, PII, and secrets never enter telemetry. Delete raw evidence after the bounded investigation/review window and append a tombstone while retaining permitted hashes/provenance/excerpts; sealed synthetic evaluation uses a separately declared retention profile. Use short-lived HttpOnly same-site sessions for named synthetic actors, enforce roles and incompatible-duty separation server-side, and require fresh reconfirmation before handoff, clearly labeling this as demo role control rather than enterprise IAM. Use forward database migrations, guarded profile-specific resets, and fresh run-specific evaluation stores.

**Models and compute.** The reference machine is an Apple M4 MacBook Air with 10 cores and 16 GB RAM. Keep a portable Docker-CPU inference profile and an adapter-compatible native Metal profile using pinned local processes; benchmark both and freeze exactly one documented profile for the sealed run. Benchmark pinned Whisper `base`/`turbo` and IndicConformer, then freeze one local ASR primary on English, Hindi, and code-switch entity accuracy, memory, and latency; never cascade silently in sealed evaluation. Run pinned AASIST only after audio-quality gates and preserve its score, threshold/version, channel metadata, quality, and provenance as a diagnostic—not identity, guilt, or authorization; a low score cannot compensate for missing evidence. Extract deterministic field candidates and spans first, then use one deterministic schema-constrained local multilingual model, initially benchmarking quantized Qwen3 4B against a smaller challenger and freezing the smallest model that passes exact-field, unsupported-field, abstention, memory, and latency gates. Validate every field against source-backed candidates/spans, preserve ambiguity, require operator confirmation, and generate authoritative explanations from structured findings and reason-code templates.

**Adapters and interfaces.** The deterministic fake adapter is canonical for safety, replay, ambiguity, and the truthful endpoint of a pending item in an existing maker-checker rail. A separately labeled RazorpayX Test Mode adapter proves authenticated API/webhook integration with dummy money but is never presented as Razorpay Approval Workflow, real approval, or live execution. Both accept only a valid unconsumed grant plus the minimum exact Payment Intent. Verify Razorpay webhook HMAC over transient raw bytes, retain only hashes/redacted metadata, deduplicate event IDs, and map recognized events only into adapter/reconciliation state; they cannot rewrite the frozen intent or historical Policy Outcome. Reconciliation may query by the original reference but cannot create a new payout.

**UI and deployment.** Generate Vite/React types from authoritative OpenAPI/JSON Schema and keep all safety-critical behavior server-side. Provide visibly distinct `local-live` and synthetic `hosted-fixture` modes. The guaranteed deployment is local Docker Compose with `web`, `api`, and `worker`, explicit database/vault/model/export mounts, health checks, and a headless evaluation profile; Policy Gate, grant, and handoff remain isolated modules inside the API so workers lack credentials. The optional public experience is a static GitHub Pages fixture with no uploads, analytics, keys, backend, or network calls. Neither the five-minute demo nor sealed evaluation depends on hosting or network availability.

**Observability, testing, and reproducibility.** Use allowlisted OpenTelemetry fields exported locally to JSONL/OTLP artifacts and aggregate metrics, with an optional local trace viewer; collect pseudonymous IDs, stage durations, cold/warm state, attempts, model/policy versions, outcomes/reasons, and resource measurements only. Separate liveness, readiness, and redacted capability status; required-capability degradation always fails closed. Keep simulator, independent oracle, runtime, and scorer as separately invoked packages with one-way data flow and fresh sealed-run storage. Hosted CI runs schema, state-machine/property, policy regression, grant/replay/concurrency, audit, adapter/webhook, migration, and small synthetic end-to-end tests without large weights; pinned local commands run model, latency, stress, and sealed suites and emit verifiable manifests. Commit lockfiles, schemas, small redistributable fixtures, and a hash/license/source-aware resource manifest; download weights/datasets into a verified gitignored cache and provide acquisition instructions or synthetic substitutes where redistribution is restricted.

**Cost and evolution.** Required API spend is zero: local inference, SQLite, Docker/native runtimes, local observability, the fake adapter, RazorpayX Test Mode, and static hosting form the baseline. Keep the optional spend ceiling at ₹2,500 and activate it only when a named local development gate fails and a hosted STT or extraction challenger wins a measured comparison on synthetic/redacted evidence with reviewed terms; publish metric gain, latency, data path, and per-case cost, while retaining the local profile as the reproducible authority. External IAM, Postgres/object storage, KMS, reviewed hosted processors, live telephony, customer evidence, production KYC, and live approval/payment rails remain explicit post-MVP hardening work rather than hidden Buildathon dependencies.
